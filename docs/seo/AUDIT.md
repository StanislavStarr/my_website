## 1. Подтверждённые проблемы

### C1. Сайт закрыт от индексации целиком — КРИТИЧНО
Доказательства (прод, 16.11.2026):
- `GET /robots.txt` → `User-agent: *` / `Disallow: /`
- `GET /sitemap.xml` → пустой `<urlset>` без единого URL
- Все страницы (`/`, `/ru`, `/work/ekhonish`): `<meta name="robots" content="noindex, nofollow"/>`
- В HTML нет `<link rel="canonical">`, нет `hreflang`, нет `application/ld+json`

Причина (по коду): `src/lib/seo.ts` включает индексацию, только если заданы
`SITE_URL` и `ENABLE_INDEXING=true`. Без `SITE_URL` не выводятся canonical,
hreflang, JSON-LD и sitemap (`StructuredData.tsx`, `sitemap.ts`).
Что переменные не заданы в Vercel, — вывод из поведения прода; настройки
проекта в Vercel я не открывал.
`README.md` и `docs/VERIFICATION.md` прямо фиксируют: домен не выбран, индексация выключена.

Следствие: пока это не исправлено, остальные SEO/GEO-работы не дают эффекта.
Поисковики и AI-краулеры, уважающие robots.txt, не читают сайт.

### C2. Нет собственного домена
Сайт живёт на `*.vercel.app`. По `docs/VERIFICATION.md`: «production domain,
hosting, Search Console, external analytics — not connected yet».

### C3. Нет инструментов измерения и верификации
В HTML нет meta-тегов верификации (Google, Bing, Yandex), нет аналитики.
Подтверждено по `docs/VERIFICATION.md` и поиску по живому HTML.

### C4. Весь контент о услугах — одна страница
Услуги — шесть блоков `<h3>` на главной. Отдельных URL под запросы вроде
«разработка Telegram Mini App», «React Native приложение», «PWA / SaaS»,
«SEO и GEO» нет. Страницы кейсов (4 × 2 языка) — единственные внутренние страницы.
Подтверждено структурой `src/app`.

### C5. Часть заявленных услуг не названа в тексте
В `messages/*.json` (услуги, FAQ, meta) отсутствуют: **Telegram-боты**, **SPA**,
**фулстек** как отдельная формулировка (есть «Full-stack» только в ролях кейсов).
PWA и Mini Apps упомянуты в одном абзаце `s3p`. «SEO и GEO» подано как
«SEO & AI search» без слова GEO.

### C6. Title, description и H1 слабо отражают спрос
- H1: «From idea to a working product» / «От идеи до работающего продукта» — без
  ключевых слов услуги (это допустимо как дизайн-решение, но запросная привязка
  держится только на title/description).
- Title содержит «Web & Mobile Developer» / «Веб- и мобильная разработка» —
  нет Telegram, SaaS, фулстека, нет указания на заказчика (бизнес).
- На страницах кейсов `og:type` = `website`; description дублирует `summary`.

### C7. Ошибки и пробелы в JSON-LD (код; сейчас не выводится из-за C1)
`src/components/StructuredData.tsx`:
- `areaServed` — `{'@type':'Country', name:'RU'}`: ISO-коды в поле `name`, а не
  названия или `addressCountry`. В списке только страны СНГ + «Worldwide (remote)» —
  Европа и Америка не названы.
- Все 6 `Service` имеют один и тот же `url` с фрагментом `#services`
  (отдельных страниц нет — см. C4).
- `sameAs` у Person содержит только Telegram: нет GitHub/LinkedIn и т.п.
- `FAQPage` на главной: после 7 мая 2026 Google не показывает FAQ rich results
  для всех сайтов — оставить можно, пользы для выдачи Google не ожидать (Info).
- Язык: `Person.name` — «Stanislav Sinitsyn» на RU-версии (в RU title —
  «Станислав Синицын»); альтернативное написание в `alternateName` не задано.

### C8. Open Graph
Одна общая картинка `/og-image` для всех страниц и языков, текст только
на английском, одинаковая для кейсов (`src/app/og-image/route.tsx`).

### C9. Конверсионный путь сокращён
Форма брифа (`<Brief />`) закомментирована в `Contact.tsx`; остаются Telegram и
email. API `/api/contact` в коде есть, но на странице не используется.
Для цели «заявки» это влияет на конверсию, а не на ранжирование.

### C10. Мелкие технические пункты
- `/favicon.ico` → 404 (есть только `icon.svg`).
- `/llms.txt` → 404 (файл необязателен; Google его не использует).
- Опечатка стиля в RU FAQ (`a4`/`q4`): «Я буду работать с тобой» — при общем
  обращении на «вы».
- `PRODUCT.md` пишет «ru default», в коде `defaultLocale: 'en'` (EN на `/`, RU на `/ru`).

### Что работает (подтверждено)
- Контент отдаётся в HTML без JS (SSG), `<html lang>` корректен (`en` / `ru`).
- Один `<h1>` на странице, структура h2/h3 логична.
- Несуществующие URL → настоящий 404 (`/work/nope`, `/ru/work/nope`).
- HSTS включён; `/en` → `/` (307), `/ru/` → `/ru` (308): дублей нет.
- Код sitemap уже содержит `alternates.languages` с `x-default`;
  `pageMetadata` генерирует canonical и hreflang — **после** задания `SITE_URL`.
- Уникальные title/description для каждого кейса и языка.
- `alt` у портрета задан, у изображения указаны width/height.

## 5. Hreflang / международное SEO (16.11.2026)

Метод: локальная сборка с `SITE_URL=https://example.com ENABLE_INDEXING=true`
(тестовый домен, прод не затронут); живой прод для hreflang проверить нельзя из-за C1.

| Проверка | Результат |
|----------|-----------|
| Теги `<link rel="alternate" hreflang>` на `/`, `/ru`, `/work/medtech`, `/ru/work/medtech` | есть `en`, `ru`, `x-default` (→ EN) |
| Взаимность (каждая версия ссылается на обе и на себя) | ✅ |
| Canonical на себя в каждой языковой версии | ✅ |
| `<html lang>` | `en` / `ru` соответствует URL ✅ |
| Sitemap: 10 URL, у каждого `xhtml:link` alternates | ✅ |
| `robots.txt` при включённой индексации | `Allow: /` + `Sitemap:` ✅ |
| Редиректы `/en` → `/` (307), `/ru/` → `/ru` (308) | дублей нет ✅ |
| Паритет переводов EN/RU | набор ключей `messages/*.json` совпадает; контент кейсов есть на обоих языках ✅ |

**Вывод:** реализация hreflang корректна и заработает сразу после задания `SITE_URL`
и `ENABLE_INDEXING=true` на проде (это снова C1). Новых ошибок нет.

Наблюдения (ГИПОТЕЗЫ / замечания, не ошибки):
- Hreflang задан только по языку (`en`, `ru`), без региональных вариантов. Для
  одной EN-версии на Европу и США и одной RU-версии на РФ/СНГ это нормально;
  `en-US`/`ru-RU` дублировать не нужно.
- `x-default` указывает на EN. Для пользователей РФ/СНГ без выбора языка
  автоперенаправления нет (`localeDetection: false`) — это допустимо для SEO.
- Canonical главной выводится как `https://example.com` (без `/`), в sitemap —
  `https://example.com/`. Для корня это эквивалентно, но стоит держать единообразно.
- Страны (РФ, СНГ, ЕС, США) различаются только текстом `areaServed` в JSON-LD
  (см. C7); отдельных гео-сигналов нет.
